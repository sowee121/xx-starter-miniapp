## A. 架构与边界

**本类条目**：[A1](#a1) · [A2](#a2) · [A3](#a3) · [A4](#a4) · [A5](#a5) · [A6](#a6)

<a id="a1"></a>

### A1 · 服务端为唯一数据源，本地只存快照
**规则**：星星/贴纸/进度/每日任务/热力等用户业务数据一律以服务端为权威，客户端只缓存快照、不乐观累加；只有纯设备偏好（音量档位）才存本地。写失败必须落本地队列待重试（见 B4），禁止"本地自欺式累加"。
**适用**：判断业务数据该存哪端；排查"数字回落/清零"类问题。
**出处**：`miniprogram/README.md`。

<a id="a2"></a>

### A2 · 云调用收敛到单一出口
**规则**：所有 `wx.cloud` 调用只经 `utils/cloud.js` 一个封装模块，统一 8s 超时、统一返回 `{ ok, data, error }`，失败不自动弹窗、由调用方决定兜底。避免请求散落页面且无人负责超时与降级。
**适用**：新增任何云调用；排查"请求散落、超时无兜底"。
**出处**：`miniprogram/README.md`。

<a id="a3"></a>

### A3 · 媒体资源同包隔离（真机硬约束）
**规则**：页面与它引用的图片/音频必须在同一代码包内（或主包 `/static/`）；**模拟器能显示 ≠ 通过**，跨包引用真机必炸。子包可读主包，主包不可读子包；禁 `/subpkg/B/static/...` 动态跨包拼接。
**适用**：新增/移动图片音频、写动态路径时把它当硬约束而非建议。
**出处**：`.cursor/rules/wechat-subpackage-media.mdc`。

<a id="a4"></a>

### A4 · 主包瘦身：按引用下沉
**规则**：主包只放启动页 + 被多包共用的全局组件/工具；只被单个分包引用的组件与数据必须下沉到该分包。落位决策表 =「被多个包引用 → 主包；单包专用 → 下沉」。
**项目实证**：主包仅 `pages/home` + 13 组件 + 12 utils；英语词库等仅分包使用的 JS 不进主包。
**适用**：新增组件/工具时的落位决策、主包体积告警处理。
**出处**：`miniprogram/README.md`。

<a id="a5"></a>

### A5 · 拆包"枢纽 → 产物"单向同步
**规则**：内容存在多份复制产物时只允许一个"枢纽"作编辑源，其余由同步脚本生成；直接手改产物会被门禁拦回。同步脚本要幂等（内容未变不写盘）。
**项目实证**：8 个英语分类包的 `lib/`、`detail/detail.{wxml,json}` 由 `scripts/sync_english_runtime.js` 从 `english` 枢纽同步。
**适用**：改分类内容页/词库时，永远改枢纽再跑脚本。
**出处**：`.cursor/rules/wechat-subpackage-media.mdc`。

<a id="a6"></a>

### A6 · 跨端契约常量：改一端必须同步另一端
**规则**：被前端与后端共享的业务常量，两处定义必须一致；单侧改动必须在提交说明里点名"同步了哪一端"。
**项目实证**：`dailyTasks.SCHEMA=10`↔`utils/daily-tasks.js`；`bumpHeat.KEEP_MONTHS=12`↔`utils/activity.js`；贴纸价目 `REWARDS`↔`subpkg/shop/content/stickers.js`；`addStars` 的 `reason` 白名单↔各 detail 页。
**适用**：改任务模板、热力窗口、贴纸价目、新增发星场景。
**出处**：`cloudfunctions/README.md`。

## B. 数据一致性与并发（同类项目最值钱的部分）

**本类条目**：[B1](#b1) · [B2](#b2) · [B3](#b3) · [B4](#b4) · [B5](#b5) · [B6](#b6) · [B7](#b7) · [B8](#b8) · [B9](#b9)

<a id="b1"></a>

### B1 · 加积分必须幂等：业务键做主键 + 条件认领
**规则**："加积分/加次数"类写操作要扛住连点与重试：客户端生成业务键（`clientId`）作为 `star_logs` 的 `_id` 防重复落库；再用条件更新认领未入账记录（`credited:false→true`），认领成功才 `_.inc(delta)`；单次增量设上限（`MAX_DELTA=6`）。"先写占位（已存在即忽略）→ 条件认领 → 增量"三步缺一不可。
**适用**：任何加积分/加次数类写操作。
**出处**：`cloudfunctions/README.md`。

<a id="b2"></a>

### B2 · 扣减/兑换用条件更新，禁止先读后写
**规则**：余额、库存扣减必须以"条件满足才更新"的原子写实现；预读只用于返回友好错误（`invalid_reward/no_user/not_enough_stars`），真正的扣减条件是 `stars >= cost` 且未拥有，`updated===0` 返回 `exchange_conflict`。先读后写在并发/连点下必然超扣。
**适用**：扣减、兑换、库存类操作。
**出处**：`cloudfunctions/README.md`。

<a id="b3"></a>

### B3 · 重置纪元（epoch）作废在途旧响应
**规则**：提供"一键清空用户数据"的产品，每次重置都要写入世代号（`starsResetAt`/`heatResetAt`）；客户端把真实发起时刻拼进幂等键（`clientId` 形如 `${Date.now()}-xxx`），服务端发现请求早于最近重置即整笔作废并返回 `stale`——否则迟到的旧响应会把已清空的数据"顶回去"。
**适用**：任何带"清空数据"功能的产品；延迟响应覆盖新状态的场景。
**出处**：`cloudfunctions/README.md`。

<a id="b4"></a>

### B4 · 权威余额单调采纳 + 本地重试队列
**规则**：客户端以服务端确认的余额为准、成功只增不减，不做乐观累计；失败写入有限队列（`retry-queue`，上限 200）带幂等键，联网自动冲刷。**"已发起"不等于"已落库"，本地测试无法证明写入成功。**
**适用**：理解"涨星后回落/不变"现象；新增积分入口。
**出处**：`README.md`、`miniprogram/README.md`。

<a id="b5"></a>

### B5 · 新增文档必须显式写归属人字段
**规则**：云端不自动注入 `_openid` 时，所有新增文档必须显式写入——漏写会静默产生"按用户永远查不到"的空壳记录。把这条做成代码审查项 + 单测全局断言。
**项目实证**：`completeProgress/checkinTask/dailyTasks.sync` 曾漏写，产生 `progress` 39 条 + `task_logs` 10 条空壳。
**适用**：写任何新增文档的后端函数。
**出处**：`cloudfunctions/README.md`。

<a id="b6"></a>

### B6 · "查不到就建档"必须幂等并自愈
**规则**：并发"先查后插"必然产生重复档案。后端入口应做成幂等建档：命中多档时先合并（计数相加靠幂等键防双计、集合取并集去重、状态取新）再删多余，下次调用自动收敛。
**项目实证**：历史 226 条重复 `users` 由幂等 `getOrCreateUser` 合并收敛，涉及 5 个函数。
**适用**：任何"查不到就建档"的后端入口。
**出处**：`cloudfunctions/README.md`。

<a id="b7"></a>

### B7 · 覆盖空对象/空数组必须用条件更新 + 覆盖语义
**规则**：向"清空对象/数组字段"的普通更新里传空字面量会被数据库忽略（视为没改）。清空/整体覆盖必须「按归属人 `where({_openid})` 定位 + 显式覆盖操作符（`_.set`）」，不要用业务主键 `doc(id)` 做覆盖定位（并发多档时只更新一条会残留旧值）。
**项目实证**：`update({heatDays:{}})` 被云端忽略导致热力清不掉，改 `_.set({})` 修复。
**适用**：清空字段、整体覆盖写入。
**出处**：`cloudfunctions/README.md`。

<a id="b8"></a>

### B8 · 并发写入三铁律（写任何后端前自检）
**规则**：① 建档/更新按归属人条件定位，覆盖空值用显式覆盖操作符；② 余额扣减用条件更新而非先读后写；③ 幂等靠业务键做主键或条件认领。三条都满足才允许上线，写进后端 README 固定自检清单。
**适用**：写任何后端函数前的自检。
**出处**：`cloudfunctions/README.md`「并发写入三条铁律」。

<a id="b9"></a>

### B9 · 请求顺序 = 业务顺序
**规则**：一次动作触发多笔加积分（如"答对加星"后"任务达成发奖"），后发请求必须挂在先发请求的异步回调链/微任务里排队发起，保证落库顺序与业务语义一致；顶栏在任一笔确认后刷新。
**适用**：一个动作触发多次加星的场景。
**出处**：`README.md`。

## C. 静态门禁与自动化

**本类条目**：[C1](#c1) · [C2](#c2) · [C3](#c3) · [C4](#c4) · [C5](#c5) · [C6](#c6)

<a id="c1"></a>

### C1 · 给仓库装一台"提交前门禁"
**规则**：把会静默失败的约束（资源存在性、组件注册、运行时产物一致性、命名规范、体积阈值）写进一个静态检查脚本作为唯一门禁，能拦的规则都进脚本别靠人记；门禁支持单文件局部跑与全量跑；同步类检查在内容未变时不写盘。
**项目实证**：`npm test` → `scripts/check_miniprogram.js`，内嵌英语运行时同步。
**适用**：任何改动后的自检。
**出处**：`README.md`。

<a id="c2"></a>

### C2 · 布局只用 flex-wrap + gap
**规则**：跨端一致性靠布局写法收敛：只用 `flex-wrap:wrap` + `gap`，禁 `space-between`、grid、负 margin 做整行；纵向间距一律由容器 `gap` 提供，`.block` 自身不带 margin；顶层网格不加左右 padding。规则写进门禁直接拦违规。
**适用**：写/改 wxss 与配套静态稿 CSS。
**出处**：`README.md`。

<a id="c3"></a>

### C3 · 后端本地单测：Mock SDK + 内存库
**规则**：云函数要有不联网、不部署即可跑的本地单测：Mock `wx-server-sdk` + 内存数据库，覆盖参数拒绝/正常路径/幂等并发/归属人落库；**新增后端入口必须补用例**。
**项目实证**：`npm run test:cloud`（改 `cloudfunctions/` 后必跑）。
**适用**：改后端函数后、新增函数时。
**出处**：`cloudfunctions/README.md`。

<a id="c4"></a>

### C4 · pre 钩子把门禁串进高频命令
**规则**：用包管理器 pre 钩子让"部署/发版"命令自动先跑测试，堵住跳过自检直接上线的路径。
**项目实证**：`precloud:deploy`→`test:cloud`；`premp:upload`→`npm test`。
**适用**：理解"为什么一条命令会先跑测试"；设计自己的命令链。
**出处**：`package.json`。

<a id="c5"></a>

### C5 · 体积预算与软硬阈值
**规则**：代码包体积设「软告警/硬上限」两档 + 预下载预算，数值常量化管理；新增大资源后必须跑体积检查再决定分包或上云。
**项目实证**：主包 ~1.45MB、单包 2MB 硬上限 / 1.85MB 软告警、同来源 `preloadRule` 合计 ≤2MB。
**适用**：新增分包/大图后评估风险。
**出处**：`README.md`。

<a id="c6"></a>

### C6 · 单测工具留好"只跑一个"的逃生口
**规则**：测试框架无按名过滤开关时，临时验证只能改配置（如 `TEST_CASES`）或加条件跳过——**跳过逻辑禁止提交**，提交前必须还原。
**适用**：本地只想验证单个用例时。
**出处**：`CODEBUDDY.md`。

## D. 部署与发布流水线

**本类条目**：[D1](#d1) · [D2](#d2) · [D3](#d3) · [D4](#d4) · [D5](#d5) · [D6](#d6) · [D7](#d7)

<a id="d1"></a>

### D1 · 后端改完即部署，不留本地
**规则**：后端代码改完当轮即部署到线上，只部署改过的入口（`npm run cloud:deploy -- <fn>`）；部署失败如实说明原因，禁止假装已上线。两条通道都失败才可解释放弃。
**适用**：任何后端代码改动。
**出处**：`.cursor/rules/cloud-function-auto-deploy.mdc`。

<a id="d2"></a>

### D2 · 部署双通道与"参数缺省"坑
**规则**：同一部署目标备两条通道互相兜底：IDE 通道（开发者工具 CLI）与 CI 通道（miniprogram-ci + 私钥），两者都要装依赖（`--remote-npm-install`）。CLI 常见坑是参数形态错误——IDE 通道须传 `--appid`+`--paths`，禁只传 `--project --names`，否则报 `41002 appid missing`。
**适用**：选部署通道、排查部署报错。
**出处**：`cloudfunctions/README.md`。

<a id="d3"></a>

### D3 · "上传"≠"发布到体验版"
**规则**：`mp:upload` 后只是进了"开发版本"队列，选为体验版/正式版是公众平台的另一步手动操作；临时真机验证应走"预览二维码"（`mp:preview`，二维码落 `.ci-output/`），别把每版都发成体验版。
**适用**：发版与临时真机验证。
**出处**：`docs/ci-miniprogram.md`。

<a id="d4"></a>

### D4 · 环境标识多处一致
**规则**：换环境时核对清单：运行时配置（`config/cloud.js` 的 `CLOUD_ENV`）、工程配置（`project.config.json`）、开发者工具当前选中、CI 脚本 `-e` 参数、资源桶（`config/media.js` 的 `CLOUD_BUCKET`）——四处不一致会出现"上传成功但调不通"。
**适用**：换环境、排查"上传成功但调不通"。
**出处**：`cloudfunctions/README.md`。

<a id="d5"></a>

### D5 · "本地资源模式"可能是刻意选择
**规则**：免费/低配套餐常无法放开存储 ACL（只能创建者读），导致真机其他用户看不到云端资源。此时默认走"代码包内置资源"（`USE_CLOUD=false`）是正确决策——可把资源备份到云，但别切开关、别跑清理（`assets:purge` 禁跑），除非确认 ACL 已放开。
**适用**：有人提议"把资源传云端省体积"时先确认套餐 ACL 能力。
**出处**：`cloud-assets/README.md`。

<a id="d6"></a>

### D6 · 固化一条推荐发布流水线
**规则**：把「代码 → 后端部署 → 媒体上传 → 发版」串成可照做的流水线写进 README：改代码 → `cloud:ci-deploy` →（有媒体变更）`assets:ci-upload` → `mp:upload` → 公众平台选体验版。清包内资源/裁音频等易误伤操作保持手动。
**适用**：日常发版顺序。
**出处**：`docs/ci-miniprogram.md`。

<a id="d7"></a>

### D7 · 密钥与白名单安全基线
**规则**：上传私钥/凭据必须 gitignore（`secrets/private.<appid>.key`）；丢失只能到平台重置。IP 白名单可关但风险更高，默认保持开启；新机器配置走同一份安全说明。
**适用**：配置新机器。
**出处**：`docs/ci-miniprogram.md`。

## E. 视觉与设计资产

**本类条目**：[E1](#e1) · [E2](#e2) · [E3](#e3) · [E4](#e4) · [E5](#e5) · [E6](#e6)

<a id="e1"></a>

### E1 · 多端样式稿双向同步
**规则**：有"实现端 + 静态审查稿"双份样式时，任何布局/色调改动必须同批改两侧，并建立像素单位映射（1px=1rpx，画板 750）；样式拆成同名 token/区块文件便于一一对照；交付说明列出两侧文件，故意不一致须写明原因。
**项目实证**：`styles/tokens.wxss`↔`docs/design/h5/css/tokens.css`、`pages/home`↔`home.css+home.html`。
**适用**：任何布局/尺寸/色调/间距改动。
**出处**：`.cursor/rules/h5-miniapp-style-sync.mdc`。

<a id="e2"></a>

### E2 · 静态审查稿只做 UI，不做产品交互
**规则**：给审查/演示用的 H5 静态稿禁止塞产品交互（点读/切题/答题/兑换/支付等），只做静态 UI + 纯导航跳静态帧（事件委托集中映射到 `js/nav.js`，勿逐元素绑监听）。把"哪些交互只做真机"写清楚，防止静态稿被当成线上演示。
**适用**：改审查稿；处理"在预览里点一下听听"类诉求。
**出处**：`.cursor/rules/h5-static-review.mdc`。

<a id="e3"></a>

### E3 · 设计 token 收拢纪律
**规则**：样式变量只在「值相同且语义一致」时收拢；单点值不提取；跨组件重复的同一语义值必须归并；删除 token 前全仓 grep 确认零引用。收拢不足 → 散落硬编码，收拢过度 → 语义污染。
**项目实证**：卡面色一律 `tone-*`，禁硬编码色值。
**适用**：改样式、新增色值。
**出处**：`docs/design/PLAN.md`。

<a id="e4"></a>

### E4 · "圆角面"规范要避开平台不支持的特性
**规则**：卡片/按钮要选目标环境能稳定还原的实现：圆角用普通 `border-radius`，凸起鼓边用"对角 inset 高光/压暗"（上左高光 + 下右压暗）；禁止依赖 `corner-shape: squircle` 等兼容性差的特性或"扁按钮"假阴影。视觉规范里"禁用什么"与"推荐什么"同等重要。
**适用**：做新卡片/新控件。
**出处**：`docs/design/PLAN.md`。

<a id="e5"></a>

### E5 · 尺寸与热区要有档位表
**规则**：圆角/字号下限/点击热区/模块间距都应有一张可查档位表（含嵌套公式），新控件从表取值而非随手写数；热区设默认下限与例外清单。
**项目实证**：圆角 `card56/tile48/bar40/thumb28/cell16/pill999`（thumb≈card−pad）；字号下限 28rpx；热区 ≥152rpx²（紧凑 128）。
**适用**：写任何控件样式。
**出处**：`docs/design/PLAN.md`。

<a id="e6"></a>

### E6 · 关键控件"结构定稿"后禁止整图替代
**规则**：已被 CSS 结构定稿的控件（播放按钮 = CSS 绿底 + 鼓边 + 小原子图标）禁止再生成"整图版"；替换图标、重绘、换色都被视为破坏定稿。纪律：能用 CSS 的不生图、已定稿的默认只读。
**适用**：出现播放相关视觉需求；覆盖定稿素材前。
**出处**：`.cursor/rules/image-asset-generation.mdc`。

## F. 素材与音频流水线

**本类条目**：[F1](#f1) · [F2](#f2) · [F3](#f3) · [F4](#f4) · [F5](#f5) · [F6](#f6) · [F7](#f7) · [F8](#f8)

<a id="f1"></a>

### F1 · 先原子后合成
**规则**：素材生产走"逐个生成可复用原子（一图一主体、透明底）→ 再用原子合成"的流程，禁止先出合成图再抠取；配套去背/归一化/同步脚本，勿手写有损压缩。
**项目实证**：`chroma_to_png.py` → `normalize_atoms.py` → `sync_package_images.py`。
**适用**：任何新素材产出。
**出处**：`.cursor/rules/image-asset-generation.mdc`。

<a id="f2"></a>

### F2 · 覆盖必留痕
**规则**：覆盖任何已定稿素材前先把旧文件备份到带时间戳的历史目录——素材覆盖不可逆。备份与覆盖拆成两个脚本动作，覆盖前强制跑备份。
**项目实证**：`python3 scripts/backup_atom.py <文件>` → 旧图落 `atoms/_history/{名}/{时间戳}.png`。
**适用**：任何覆盖已有 PNG 的操作。
**出处**：`.cursor/rules/image-asset-generation.mdc`。

<a id="f3"></a>

### F3 · 落地尺寸统一档位
**规则**：同一用途素材统一像素档位，由脚本从大图下采样同步（列表 128px、分类详情 320px、字母图 272px）；禁止"随手压到奇怪尺寸"（如 160）或手写有损重压。档位值集中定义、脚本统一执行。
**适用**：改词图后同步；评估包体积。
**出处**：`.cursor/rules/wechat-subpackage-media.mdc`、`scripts/sync_package_images.py`。

<a id="f4"></a>

### F4 · 资源文件名必须纯 ASCII
**规则**：客户端按字面量查包内路径，中文文件名被百分号编码后就读取失败——工具环境可能放过、真机必炸。文件名一律 ASCII slug；中文重码（同音）用「拼音-码点」保证唯一（爸/八都是 `ba` → `{拼音}-{Unicode码点}.mp3`）；门禁直接拦非 ASCII 文件名。
**适用**：新增任何图片/音频文件。
**出处**：`.cursor/rules/wechat-subpackage-media.mdc`、edge-tts-batch skill。

<a id="f5"></a>

### F5 · TTS 音色语速要有定稿表
**规则**：批量语音合成前，按内容类型（逐句朗读/单词/字母名/注音/反馈音）选定音色+语速并固化成表；不同音色对特定内容有已知缺陷（吞孤立字母、注音缺字），选型避开并把缺陷案例写进表里防重踩。
**项目实证**：古诗/单字→`zh-CN-XiaoxiaoNeural` `-30%`；英语词句→`en-US-EmmaNeural` `-30%`；字母 A–Z→`en-US-JennyNeural` `-10%`（W=`double u`、Z=`zee`）；拼音韵母→`zh-TW-HsiaoChenNeural` `-10%`；算术反馈 `+20%~+60%`。
**适用**：出/改点读音频。
**出处**：edge-tts-batch skill、`docs/design/CONTENT.md`。

<a id="f6"></a>

### F6 · 音频按"使用方代码包"输出，路径写回内容
**规则**：批量音频直接写入使用它的代码包目录（防堆主包），并把运行时路径写回内容字段——页面读字段播放，禁止运行时拼路径；脚本结束打印各包体积与预算对比。
**项目实证**：TTS 直写各分包 `static/audio/`，路径写回内容文件。
**适用**：批量出音频、评估体积。
**出处**：edge-tts-batch skill。

<a id="f7"></a>

### F7 · 内容文件必须是严格 JSON
**规则**：被运行时 require 的内容配置写成"严格 JSON 的 JS 模块"（双引号、无尾逗号、无注释），裸 `.json` 在部分运行时无法可靠加载；需要说明用 `_note` 字段。
**项目实证**：`content/*.js` = `module.exports = <严格 JSON>`。
**适用**：改题库/内容配置。
**出处**：edge-tts-batch skill。

<a id="f8"></a>

### F8 · 生图前置纪律
**规则**：调用生图前先过五问：① 能否 CSS 实现？② 是否动了定稿素材？③ 用户是否明确要求生图？④ 批量前是否先出样图？⑤ 最小改动是否只做去毛刺/居中/去背而不换造型？圆底/渐变/鼓边/选中环/chip 一律 CSS 不生图。
**适用**：任何"帮我生成一张图"的请求。
**出处**：`.cursor/rules/image-asset-generation.mdc`。

## G. 协作规范（防返工）

**本类条目**：[G1](#g1) · [G2](#g2) · [G3](#g3) · [G4](#g4)

<a id="g1"></a>

### G1 · 注释写"为什么"，不写流水账
**规则**：`/** 摘要 */` 块注释只放声明上方；`//` 行注释只放逻辑行上方写理由（分支原因、时序、平台 hack、兜底）；空 `catch` 统一 `// ignore`；与对端耦合的常量注明"和谁同步"。注释掉的代码、`TODO`/`FIXME` 不入库。
**适用**：写/改任何代码。
**出处**：`.cursor/rules/code-comment.mdc`。

<a id="g2"></a>

### G2 · 提交走完整安全流程
**规则**：用户说"提交"时：`pull` → `status/diff` → 只提交本地最新工作区 → `push origin main` → 再确认对齐。禁止跳过拉取/推送、禁止旁路分支（worktree）、禁止未要求时硬重置；冲突先解决再提交，不拿远端覆盖本地未提交改动。
**适用**：用户说"提交"。
**出处**：`.cursor/rules/git-commit-flow.mdc`。

<a id="g3"></a>

### G3 · 省 token、防返工的交付方式
**规则**：一句话概括改动；给变更片段不给全量文件；长文件标路径省略未改部分；说明改动涉及哪些端、关键数值、有意没做的项。执行上：先看现有结构只改该改的；能局部替换不整文件重写；能改现有文件不新建；**禁止重复产物**；不为交差做全仓扫描。
**适用**：每次对话与交付。
**出处**：`.cursor/rules/reply-concise.mdc`。

<a id="g4"></a>

### G4 · 拿不准只问最关键的一个问题
**规则**：指令有歧义（两种改法都说得通/"按相同模式"指结构还是数值/会动定稿素材）时，只提 1–2 个最关键问题，不连环追问，确认后再动手。
**适用**：需求歧义时的兜底行为。

## H. 可复用 SOP（照做即可）

**本类条目**：[H1](#h1) · [H2](#h2) · [H3](#h3) · [H4](#h4)

<a id="h1"></a>

### H1 · 新增一个业务板块的 8 步 SOP
1. 注册代码包/路由（启动页需要时加预下载规则）；
2. 在模块清单加条目（id/标题/图标/主题/路由）；
3. 内容配置放本板块目录、媒体放本板块资源目录（**不跨包**）；
4. 复用通用卡片 + 播放入口组件，奖励发放走统一发奖工具；
5. 点击包防连点组件，反馈走统一反馈组件（弹层/行内按场景二选一）；
6. 若接入每日任务体系，前后端任务模板与 SCHEMA 一起递增；
7. 音频走批量 TTS 流水线；
8. 跑门禁（`npm test`）→ 发版。
每步都指向既有复用件，避免"新板块 = 新造一套"。详见 `miniprogram/README.md`「新增一个学习板块」。

<a id="h2"></a>

### H2 · 新增后端入口的 7 步 SOP
1. 建目录：入口 + `package.json` 依赖清单；
2. 先校验参数（缺参返回统一 `invalid_params`），再按归属人读写；
3. 新增文档显式写归属人；覆盖写用"按归属人定位 + 覆盖操作符"（B5/B7）；
4. 与客户端耦合的常量两端递增（A6）；
5. 在本地单测补用例：参数拒绝 + 正常路径 + 幂等并发 + 归属人落库；
6. 本地测试通过后即部署该入口（D1）；
7. 补两处文档：函数清单 + API 参考。
步骤 2/3/5 直接复用 B 类三铁律。详见 `cloudfunctions/README.md`。

<a id="h3"></a>

### H3 · 优先复用组件与工具，再谈新建
**规则**：把常用能力沉淀成"主包通用件 + 子包专用件"两层的组件/工具清单，随代码演进维护；新需求先查清单找复用件，确实没有才新建（并决定放通用层还是专用层）。
**项目实证**：主包 13 组件（app-shell/custom-header/star-bar/play-button/feedback-*/entry-* 等）+ 12 utils（cloud/stars/retry-queue/read-award/audio/page/tap-guard…）；单包专用件下沉（quiz-frame/sticker-card/task-row…）。
**适用**：页面开发前查复用件；"禁止重复产物"的执行基础。
**出处**：`miniprogram/README.md`。

<a id="h4"></a>

### H4 · 后端单测用例三件套 + 一条全局断言
**规则**：每个后端入口用例至少覆盖：参数拒绝、正常路径、幂等/并发；并加一条全局断言——所有新落库记录都带归属人字段（B5 的落地手段）。
**适用**：写后端单测。
**出处**：`cloudfunctions/README.md`。

## I. 排障速查（现象 → 根因 → 动作）

| 现象 | 根因 | 动作 |
| --- | --- | --- |
| 真机资源空白（工具正常） | 不支持的图片格式 / 文件名非 ASCII / 跨包引用 | 转标准格式、改 ASCII slug、资源移入同包；跑门禁 |
| 真机无声音 | 音量档位被家长端关 / 音频参数未设 / 路径不存在 | 逐项查设置、参数、路径存在性（门禁可拦路径） |
| 涨分后数字回落/不变 | 服务端权威 + 单调采纳，失败已入本地队列 | 联网等自动冲刷；**本地测试不能证明已落库** |
| 后端入口 `FUNCTION_NOT_FOUND` | 未部署或环境绑错 | 部署该入口 / 核对环境 |
| 集合不存在 | 表/集合未初始化 | 控制台初始化一次 |
| 加星一直 `invalid_params` | 幂等键缺失 / 场景不在白名单 / 增量超限 | 对照白名单补场景字段 |
| 清空后旧数据还在 | 空对象覆盖被忽略 | 改用"按归属人定位 + 显式覆盖操作符" |
| 同用户出现多条档案 | 并发"先查后插" | 幂等建档自动合并收敛 |
| CLI 报 `41002 appid missing` | 部署参数形态不全 | 按通道契约补 `--appid`+`--paths` |
| 拆包产物改了不生效 | 直接改了产物侧 | 改枢纽，跑同步脚本 |
| 主包体积告警 | 大资源堆主包 | 压缩或下沉分包 / 迁云端（确认 ACL 放开） |
| 云端资源真机看不到 | 免费套餐 ACL 仅创建者可读 | 保持本地资源模式（`USE_CLOUD=false`） |
| 上传成功但调不通 | 环境标识不一致 | 核对运行配置/工程配置/当前环境/CI 脚本四处 |

### 附录四 · 本库维护约定

1. **何时新增**：踩到新坑且根因明确、或形成可复用做法时立即补；临时现象、未验证猜测不入库。
2. **编号规则**：归入既有分类顺延编号（A7/F9…）；全新主题开新分类字母；编号一旦分配不复用不改号，外部引用才不失效。
3. **出处留底**：每条必须标注出处（文档/规则/脚本路径），便于回源核验；引用真实项目数据要写清数量与函数名。
4. **联动更新**：新增/修改条目时同步更新「关键词索引」与「附录三 场景任务索引」；本文件与线上资料库副本、`README.md` 文档导航保持同一版本。
